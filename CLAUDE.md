# KanaType — instructions for Claude

Before doing anything substantive, read these two files — they carry the full
project context (this project has a long history that predates any fresh session):

1. `HANDOFF.md` — hardware truth: pin map, the switch's real internal pairing,
   the ACTIVE-HIGH-SCAN-ONLY commitment (PCB has column pull-downs), part
   numbers, power design, RP2350 upgrade notes.
2. `Firmware/PLAN.md` — the software plan, decisions log, and milestones
   (M0 platform + M1 practice app + M3 keyboard are DONE; M2 quick-note/vault
   and M4 sync are next).

Project conventions that bite if ignored:

- Screen geometry and font roles live ONLY in `Firmware/src/kanatype/layout.py`,
  shared by firmware (`ui.py`) and the desktop renderer (`tools/render.py`).
  Never hardcode positions elsewhere. `tools/render.py` produces pixel-faithful
  previews — render before deploying UI changes; the user approves renders first.
- The physical keymap lives ONLY in `Firmware/src/kanatype/keymap.py` (board-
  verified) — it feeds both KMK and the app input driver. Matrix scanning is
  columns_to_anodes=False everywhere, non-negotiable (hardware pull-downs).
  `Firmware/tools/keychart.py` draws the board from that file (`legend`, `app`,
  `matrix`, `sw` views) — use it before and after any keymap edit. Four keys do
  NOT match a plain QWERTY reading of the silkscreen: see the key-roles table
  at the top of `HANDOFF.md`.
- `Firmware/src/kanatype/keytable.py` is GENERATED by
  `Firmware/tools/gen_keytable.py` from the device's own `lib/kmk/keys.py`
  (KMK has no enumerable keycode list). Never hand-edit it; regenerate after a
  KMK upgrade, and expect saved macros to reset since `keytable.HASH` guards
  them.
- Deploy with `Firmware/tools/deploy.ps1` (Windows) or `deploy.sh` (macOS/Linux);
  both find the drive by its CIRCUITPY label and never delete device-side libs.
- Before deploying run `python Firmware/tools/preflight.py` (compiles
  everything, then checks font roles, prompt-font styles, keymap coverage,
  deck counts, icon bounds, nvm settings round-trip, menu entries, and stale
  device-side files). It exits non-zero on anything that has bitten before.
- `Firmware/BRINGUP.md` is the on-hardware checklist for a big deploy.
- KiCad project in the repo root; production files in `production/`
  (`make_jlc_files.py` regenerates the JLCPCB BOM + placement files from a
  fresh .pos export).
- UI mockups round-trip via `Firmware/tools/mockup.py` (txt/pbm/png/bmp);
  pixel art assets are generated from txt sources in `Firmware/mockups/`.
